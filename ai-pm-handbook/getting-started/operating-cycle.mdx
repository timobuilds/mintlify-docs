---
title: The AI PM Operating Cycle
description: How product work moves from discovery to improvement
---

Each phase should produce observable evidence, not simply more documentation.

| Stage | Decision | Evidence / artifact |
| --- | --- | --- |
| Discover | Which user job matters? | Interviews and classified feedback |
| Define | What must happen? | AI PRD and acceptance criteria |
| Design | How do people interact? | Prototype and responsibility map |
| Engineer | What system can deliver? | Model/context/harness specification |
| Evaluate | Where does it fail? | Traces, taxonomy, calibrated evals |
| Deploy | Is risk acceptable? | Release gates and monitoring plan |
| Improve | Which change moves value? | Controlled comparisons and new baselines |

A cycle is complete only when a new observation changes the product decision. Avoid optimizing an internal score while neglecting user outcomes.

**Try it:** find one critical failure in an AI product and track it backward to the first design choice that could prevent it.

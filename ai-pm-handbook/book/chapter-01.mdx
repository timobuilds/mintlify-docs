Traditional product work often assumed that software behaved according to explicit rules. AI products are different: behavior is partly learned, probabilistic, and context-sensitive. That changes what a PM must specify, inspect, and own.


### Source-reported: four related jobs

Model PMs work close to model research and model quality. AI platform PMs build enabling infrastructure. AI-native PMs design products whose core value depends on models. Applied AI PMs bring AI capabilities to existing workflows. The boundaries overlap, but the quality bar and technical dependencies differ.


### Instructional synthesis: a new unit of management

The unit is not a feature screen or individual prompt. It is an end-to-end system: user intent, data, model decisions, tools, constraints, human involvement, and measurable outcomes. An attractive demo proves feasibility at best; it does not prove reliability or value.

## What PMs should own

PMs should own the job to be done, what counts as a good outcome, acceptable failure costs, authority boundaries, and release criteria. Technical teams own implementation details, but these product decisions cannot be delegated to infrastructure alone.

## Try it

Write a one-sentence job definition for an AI product. For the Scout: “Given a client brief, deliver a defensible shortlist of matching properties with sources and uncertainties, without contacting anyone or spending money without permission.”

Read further: Gupta, Model PM: https://www.news.aakashg.com/p/model-pm



## Responsibility exercise

For Scout, the PM defines the matching criteria and acceptable omissions; a domain reviewer checks example answers; engineering implements retrieval and permission checks; operations owns incident response. Agree who can change each decision. A prompt edit that changes which properties qualify is a product change, even if it requires no interface work.

**Deliverable:** name one accountable owner for requirements, dataset labeling, implementation, release approval and production monitoring. Resolve overlaps before the pilot.
